# 개발환경 세팅

## vs code

### 설치 방법

1) 브라우저 주소창에 vs code 다운로드 검색
2) 각각의 OS에 맞게 다운로드
3) 설치 후 라이선스 동의 및 기본적으로 체크된 설정을 건들이지 않고 next 또는 다음 버튼 누르기
4) 설치 완료후 vs code 띄우기
5) 다음 진행을 위해 새 파일이나 폴더를 생성하지 않는다

### 익스텐션 설정

1) 왼쪽 아이콘들이 있는 사이드바에서 큐브 모양 아이콘을 클릭 (마우스를 위에 가져다가면 extension 이라고 설명창 뜸)

2) 설치 방법
  1) 좌상단 Extension의 검색창에 익스텐션을 검색
  2) 바로 아래 뜨는 항목들중에서 일치하는걸 클릭.
  3) 중앙 페이지에서 해당 익스텐션의 install 또는 설치 버튼을 누른다

3) 다음과 같은 프로젝트의 필수 extension을 설치한다
  1) Code Runner : 코드를 우상단 '$\triangleright$' 버튼만 누르면 편하게 실행 가능
  2) Python : vscode 내에서 python과 관련된 편한 부가기능을 제공
  3) ESLint : JS에 대한 문법 오류 검사
  4) Jupyter : jupyter note를 편하게 쓰기 위한 부가기능
      - (참고 : 주피터 노트북은 class2 ML에서 다루기로 함. 구글 코랩은 편의성이 좋지만, 성능 제약/세션 초기화/프로젝트 통합 이슈; 각자 로컬에 주피터 커널 등록은 conda와 주피터 설정이 복잡하므로, 나중에 class2 시작시 원격 서버(강의자 리눅스 컴퓨터)로 URL 연결 예정)
  5) vscode-pdf : vscode 내 PDF 열람
  6) (윈도우) WSL
    - vscode가 윈도우 내 설치된 WSL을 인식하고 사용할 수 있게 도와줌
  - 주의사항 : 익스텐션에서 설치한 기능들이 곧 해당 프로그램은 아님. 관련된 프로그램을 더 편하게 사용하도록 도와주는 장치.
    - ex) 익스텐션 중 'Python' -> 컴퓨터에 파이썬을 설치한게 X.

## WSL, Homebrew

- 대부분의 개발 환경. 또는 편리한 개발 환경을 위해서는 Linux 운영체제를 사용하는 것이 권장된다.
  - 운영체제(OS)는 사용자가 컴퓨터를 이용할 수 있도록 도와주는 시스템이다.
    - ex) Linux(Ubuntu, Android), Windows, macOS 등
  - 개발에 리눅스가 권장되는 이유는 대부분의 서버가 리눅스를 기반으로 동작하며, 오픈소스 및 무료이고, apt 같은 패키지 관리자 등의 기능이 개발에 압도적으로 편리하기 때문.
  - 한때 맥OS 또한 리눅스와 비슷한 구조와 터미널 명령어들을 공유하기 때문에 '개발자는 애플'이란 인식이 있었으나 WSL 등장 이후 애플 생태계와 관련된 특정 분야가 아니면 거의 밀림
  - 단 본 강의 수준에선 mac에 굳이 리눅스를 설치하지 않아도 된다 (대신 homebrew 필요)

### WSL(Ubuntu) for windows

  - WSL은 윈도우에서 리눅스를 사용하게 해주는 기술이다
    - 리눅스 배포판중 가장 범용적인 우분투를 설치해보자
  
#### 윈도우에서 WSL와 우분투 설치하기 

- wsl과 기존 리눅스 확인
  - 윈도우 시작하기 창을 열고 'powershell'을 검색한다
  - powershell을 우클릭하고 '관리자 권한으로 실행'을 누른다
  - 파워쉘 창에서 다음과 같이 검색한다

```powershell
wsl --status
wsl --version
wsl --list --verbose
```
- (기존 리눅스가 설치되었을 때)

```powershell
wsl --shutdown
wsl --unregister (OS 이름) # 그냥 붙여넣기 하지 말고 (OS 이름)은 설치된 것으로 적절히 바꾸자 ex) Ubuntu
wsl --uninstall
```
- WSL 설치

```powershell
# WSL과 기본 Linux 배포판 설치
wsl --install

# 설치 가능한 배포판 확인
wsl --list --online

# (여기서 더 복사하지 말고 멈출것)

# (os이름) 배포판 설치
wsl -d --install (os이름)

# 설치된 배포판 확인
wsl --list --verbose

# WSL 상태 확인
wsl --status
```

- 윈도우 시작하기 창에 WSL과 Ubuntu 프로그램 생겼을 것이다
  - 들어가서 비밀번호 설정 (윈도우 비번 = WSL 비번을 아주 강력하게 추천한다. 까먹으면 매우 곤란)
  - 적으로 /mnt/...로 다이렉트될 것이다. WSL과 윈도우는 파일을 공유한다. 단, WSL에서 윈도우를 마운트 하는 식으로 공유한다.

### Homebrew for macOS

- Homebrew는 macOS에서 개발 도구와 프로그램을 설치·관리하는 패키지 관리자다.
  - Ubuntu의 `apt`와 비슷한 역할을 한다.
  - macOS에서는 기본 터미널 셸로 zsh를 사용하지만, 아래 명령은 터미널에서 그대로 실행하면 된다.

#### 설치하기

1) macOS에서 터미널(Terminal)을 연다. (응용 프로그램 → 유틸리티 → 터미널)
2) Homebrew 공식 사이트([brew.sh](https://brew.sh))의 설치 안내에 있는 명령을 복사해 터미널에 붙여넣고 실행한다.

```bash
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"
```

3) 설치 중 비밀번호를 물어보면 Mac 로그인 비밀번호를 입력한다.
   - 비밀번호 입력 중에는 화면에 글자가 표시되지 않는 것이 정상이다. 입력을 마치고 Enter를 누른다.
4) 설치가 끝나면 터미널에 표시되는 `Next steps` 안내를 확인한다.
   - Homebrew가 설치된 경로를 셸 설정에 등록해야 `brew` 명령을 사용할 수 있다.
   - 아래는 기본 설치 경로를 사용하는 경우의 예시다. 본인 터미널에 표시된 안내가 다르면 화면의 명령을 우선해서 따른다.

```bash
# Apple Silicon (M 시리즈) Mac
echo 'eval "$(/opt/homebrew/bin/brew shellenv)"' >> ~/.zprofile
eval "$(/opt/homebrew/bin/brew shellenv)"

# Intel Mac은 위 두 줄 대신 아래 두 줄을 사용한다
echo 'eval "$(/usr/local/bin/brew shellenv)"' >> ~/.zprofile
eval "$(/usr/local/bin/brew shellenv)"
```

5) 설치와 경로 등록이 되었는지 확인한다.

```bash
brew --version # Homebrew 버전 출력
brew doctor # 설치 상태 점검
```

#### 간단한 사용법

```bash
brew update # 설치 가능한 패키지 목록과 Homebrew 정보 업데이트
brew install git # 터미널용 프로그램 설치 예시
brew install --cask visual-studio-code # macOS 앱 설치 예시
brew list # Homebrew로 설치한 항목 확인
```

- 터미널 명령줄 도구는 `brew install`, 일반 macOS 앱은 `brew install --cask`로 설치한다.
- Homebrew 설치 명령은 공식 사이트에서 복사한다. 인터넷에서 찾은 다른 설치 스크립트는 실행하지 않는다.

## 디렉토리와 간단한 bash 조작

- 간단한 bash 조작 겸 폴더를 만들어 보자.
  - 엄밀하게는 macOS의 경우 shell script로 zsh를 쓰고 리눅스(우분투)는 bash를 사용한다
    - 둘 다 똑같은 unix 계열 shell script이고, 많은 명령어를 공유하지만 약간의 차이가 있다. (수업에 방해될 정도는 아님)
    - 또한 OS 디렉토리 구조 또한 mac과 linux가 차이가 존재한다. (/home vs /User 등)
    - 단, 이 수업에선 편의상 터미널 명령어를 bash로 지칭하자. (더 궁금한게 있으면 검색과 챗봇 질문을 하자 <- 강추)

- mac/linux (복사하지 말고 한줄씩 쳐보자)

```bash
sudo apt update # apt 패키지 관리자의 패키지 목록 업데이트

sudo apt upgrade # 프로그램 업데이트

sudo apt autoremove # 업데이트로 인해 사용되지 않은 프로그램 정리

sudo apt install python3 # 파이썬 설치

sudo apt install pip # 파이썬의 패키지 관리자

cd ~ # /home 디렉토리 이동. 'cd (폴더 이름)' : 폴더로 이동

ls # 현재 위치에서 폴더 리스트 출력

ls -al # 숨겨진 폴더(-a)와 세부사항(-l)도 출력. 인자는 결합할 수 있다 (-al)

cd /Document # 개인적 취향이지만 다수의 개발자는 이 폴더 내에 프로젝트 만드는걸 선호

cd .. # 상위 폴더로 빠져나오기. '..' : 상위 폴더, '.' : 현재 폴더

# 다시 /Document로 돌아가보자

mkdir ./testFolder # 현재 폴더 위치에 'testFolder' 폴더를 만든다 ; 'mkdir (경로)/(폴더 이름)
# 기본적으로 bash에서 경로가 필요한 경우 경로에 대해 현재 위치를 생략할 수 있다; ex) mkdir testFolder
# 그래도 헷갈리면 ./ 붙여주자 

# 만들어졌는지 폴더 리스트를 출력해보고 test 폴더로 들어가보자

nano testTxt.txt # nano라는 터미널 기본 텍스트 편집기. testTxt 이름의 txt 파일을 만듬
# 기존 파일이 있다면 그 파일을 편집하게 된다

# nano에서 'hello, nano! (엔터) hello, ML study' 라고 쳐보자
# 기본적인 커서 이동은 화살표로 할 수 있다

# ctrl + o를 눌러 저장하고, ctrl + x를 누르면 나가진다

# 잘 txt파일이 저장되었는지 확인 (명령어 쳐서)

cat ./testTxt.txt # 현재 폴더의 testTxt.txt 내용 출력

cp ./testTxt.txt ./testTxt-copy.txt # 파일 복사: 원본은 두고 복사본을 만든다
mv ./testTxt-copy.txt ./renamed.txt # 파일 이동 또는 이름 변경: 같은 폴더 안이면 이름 변경

# 폴더를 복사할 때는 -r을 붙인다
cp -r ./testFolder ./testFolder-copy # testFolder와 그 안의 내용을 복사

# 다른 폴더로 파일을 옮길 수도 있다
mv ./renamed.txt ./testFolder/renamed.txt # 파일을 testFolder 안으로 이동

rm ./testTxt.txt # 현재 폴더의 testTxt.txt 삭제

# /Document로 돌아가보자

rm -rf ./testFolder # 디렉토리의 경우 -r 인자 (하위 내용까지 재귀적으로 없앰), -f 인자 (폴더/디렉토리 삭제) 필요
# -r만 쓰이는 경우는 있어도 -f만 쓰이는 경우는 잘 없으니 따로 쓰지 말고 폴더 없애고 싶으면 -rf

# 즉석 실습
# (1) /Document에 qwer 이름의 폴더를 만들고 폴더 리스트 출력
# (2) qwer에 들어가서 asdf.txt 파일을 만들고 'zxcv' 라고 내용을 적기. 그리고 내용을 터미널에 출력
# (3) qwer 폴더 삭제
# (4) ~/Document/ML_study 폴더를 만들고 들어가기

echo 'bash 기본 조작 끝!' # 터미널에 '' 안에 있는 내용 출력
```

## git과 github

- 둘 다 개발자들에게 산소호흡기다. 이거 없으면 게임 원코인으로 하는거나 마찬가지다.

### git

- git : 코드를 원격 서버에 저장하고, 각 버전별로 관리할 수 있게 도와준다.
  - 과거/최근 버전으로 이동, 같은 저장소를 쓰는 컴퓨터끼리 공유, 새 분기 버전을 생성/통합 등
  - 이 수업에선 다음 프로젝트를 위한 최소한만 가르치겠다.

- git 설치 : 
  1) vs코드를 키고 상단 File, Edit, ... 있는 바에서 Terminal -> new terminal
  2) 'sudo apt install git' 후 지정한 비번 입력 (우분투에 기본 포함인 경우도 많음)


### github

- 코드를 원격으로 저장하는 원격저장소다. 공개 원격저장소중엔 가장 유명하다
  - 개발자 생태계에선 깃허브가 일종의 포트폴리오가 되기도 한다.
  - 코드 저장 뿐만이 아닌 코드 공유와 지식 공유도 하기도 한다.

1) 깃허브 회원 가입 : 뭐 독자들이 충분히 할 수 있을거같고 (장난입니다)
    1) 중앙에 대문짝만한 이메일 창이랑 'sign up for github', 우상단에 sign up으로 회원 가입
    2) 우상단 sign in으로 들어가기

2) vs코드와 깃허브 연결 : 좌하단 초상화 아이콘 클릭 -> sign in ...
    - 그러면 다른 컴퓨터에서도 내 깃허브 계정만 있으면 vs코드 세팅을 연동할 수 있다
    - github 관련 귀찮음 줄어드는 것도 덤

3) 레포지토리 생성
    1) (브라우저에서) 우상단 바에서 '+' 버튼 -> new repository
    2) 레포지토리 이름을 적당히 짓고 바로 create repository

4) 레포지토리 조회
    1) 좌상단 고양이 아이콘을 누르면 다시 내 계정 메인화면
    2) 왼쪽 바에 'Top reopsitory'가 뜬다 하지만,
    3) 고양이 아이콘 옆에 $\equiv$ 모양 아이콘 -> All repository -> my repository 에서도 볼 수 있다

5) git을 통해 github와 내 프로젝트 연결
    1) 터미널에서 ML_study 폴더에 가서
    2) 다음의 bash코드를 한줄씩 쳐보자
        - (깃허브에서 '…or create a new repository on the command line'랑 같음)

```bash
echo "# ---" >> README.md # '# ---' 내용을 README.md 이름의 파일로 저장
git init # .git 파일을 생성 (폴더를 처음 만들 때)
git add README.md # 깃 상태에 README 파일을 추가한다
git commit -m "first commit" # commit은 git에 변경사항을 확정시 사용한다 (아직 업로드 X)
# -m 'first commit'은 이 확정에 이러한 메세지를 달겠다는 거다
git branch -M main 
git remote add origin (URL link) # 
git push -u origin main
```

6) 레포지토리 삭제
    1) 해당 레포지토리에 들어가서 상단에 setting(톱니바퀴 아이콘) 클릭
    2) 스크롤을 내려서 Danger Zone의 'Delete this repository' 클릭
    - 주의: GitHub 레포지토리를 삭제해도 내 컴퓨터의 프로젝트 폴더와 파일은 자동으로 삭제되지 않는다. 반대로 내 컴퓨터의 파일만 있다고 해서 GitHub에 백업된 것은 아니다.

7) 삭제한 레포지토리 대신 새 레포지토리에 기존 프로젝트 연결하기
    - GitHub에서 레포지토리를 삭제했지만 내 컴퓨터의 프로젝트 폴더는 남아 있는 경우다.
    - GitHub에서 새 레포지토리를 만든 뒤, 해당 레포지토리의 주소(URL)를 복사한다.
    - 새 레포지토리는 비어 있는 상태로 만드는 것을 추천한다. README, license, .gitignore를 GitHub에서 먼저 만들면 로컬 프로젝트와 이력이 달라져 처음 push할 때 추가 작업이 필요할 수 있다.
    - VS Code 터미널에서 기존 프로젝트 폴더로 이동한 뒤 아래 명령을 한 줄씩 실행한다.

```bash
git status # 현재 프로젝트가 git 저장소인지, 변경사항이 있는지 확인
git remote -v # 현재 연결된 원격 저장소 주소 확인

# 기존 origin 주소를 새 레포지토리 주소로 바꾸기
git remote set-url origin (새 레포지토리 URL)

# 만약 'No such remote: origin'이라고 나오면 origin을 새로 등록한다
git remote add origin (새 레포지토리 URL)

git remote -v # 새 주소로 바뀌었는지 확인
git add . # 프로젝트의 변경사항을 업로드 대상으로 추가
git commit -m "reconnect project repository" # 변경사항을 하나의 버전으로 기록
git branch -M main # 현재 브랜치 이름을 main으로 맞춘다
git push -u origin main # GitHub에 처음 업로드하고 이후 push의 기본 연결을 설정
```

- `git remote set-url`과 `git remote add` 중 하나만 실행하면 된다. `origin`이 이미 등록되어 있으면 `set-url`, 등록되어 있지 않으면 `add`를 사용한다.
- `git commit`에서 'nothing to commit'이 나오면 이미 커밋된 상태일 수 있다. 이 경우 `git add`와 `git commit`은 건너뛰고 `git push -u origin main`을 실행한다.
- `git push`에서 로그인이나 권한 오류가 나오면 VS Code 또는 브라우저에서 올바른 GitHub 계정으로 로그인했는지 확인한다.

8) 다른 컴퓨터에 레포지토리 클론하기
    - 새 레포지토리에 프로젝트가 올라간 상태라면, 다른 컴퓨터에서는 `git clone`으로 프로젝트를 내려받을 수 있다.
    - 먼저 GitHub 레포지토리 페이지에서 초록색 `Code` 버튼을 누르고 HTTPS 주소를 복사한다.
    - 터미널에서 프로젝트를 둘 상위 폴더로 이동한 뒤 실행한다. 이미 같은 이름의 폴더가 있으면 그 안에 클론할 수 없으니 상위 폴더에서 실행한다.

```bash
cd ~/Documents # 프로젝트를 둘 상위 폴더로 이동 (각자 원하는 위치 사용)
git clone (복사한 레포지토리 URL) # 프로젝트를 내려받고 원격 저장소 연결도 설정
cd (레포지토리 이름) # 새로 만들어진 프로젝트 폴더로 이동
git remote -v # origin이 GitHub 주소로 연결되었는지 확인
git status # 현재 브랜치와 작업 상태 확인
```

- 클론하면 `.git` 폴더와 원격 저장소 연결이 함께 만들어지므로, 클론한 폴더 안에서 다시 `git init`이나 `git remote add origin`을 할 필요가 없다.
- 레포지토리를 삭제한 뒤 새로 만들었다면 기존 URL이 달라졌을 수 있다. 반드시 새 레포지토리의 URL을 복사한다.
